## 4. Transport root cause

`antares-client==1.14.0` `search()` is `_list_all_resources`. It runs
`requests.get` per page and follows `links.next` until it is null, inside
one `next()`. There is no page, byte, whole-iterator time, cycle, scheme or
origin bound. `requests` follows up to 30 redirects anywhere. P2 node,
depth and search budgets bound iterators, not HTTP.

Production pagination is real. The G6.2 journals failed on the next page
after 40 and 30 rows, so pages are a divisor of 10 rows. Followed links
were absolute, because the client cannot request relative ones.

Only `search` paginates. Fetch and connectivity make single requests and
are unchanged.

## 5. Final transport architecture

See qualification document section 2.

* **Activation.** It is P2-only and opt-in. It is reachable only from a
  `P2ProofProfile` carrying exact `P2TransportLimits`, a sealed
  `arnor-commissioning` capability, no injected callables, the pinned
  client, the official URL and the 60 s timeout.
* **Paginator.** `_GuardedListing` uses the client's URL, parameters,
  schema, order, laziness and termination.
* **Per-iterator bounds:**
  * pages and consecutive empty continuing pages;
  * decoded per-page and per-iterator bytes, plus declared lengths;
  * a whole-iterator deadline, also enforced within a page;
  * exact connect and read timeouts;
  * redirects per page.
* **Validation.**
  * Continuations must be plain absolute HTTPS, same origin, exact
    `/v1/loci`, and never repeated.
  * Redirects are validated before any request.
  * Every exchange goes straight to the transport adapter, so redirect and
    error bodies are never read.
* **Failure.** Refusals are typed (`P2TransportGuardError`, non-retryable).
  They are recorded as `attempt_error` / `p2_transport_guard` with the exact
  exception type, which is terminal for the night. HTTP ≥ 400 and socket
  failures stay retryable within the unchanged per-node attempts.

* **D2:** `Session.send` read redirect bodies without a ceiling.

## 6. Finite-pagination equivalence evidence

`Locus` objects and records in identical order, after the identical HTTP
request sequence, for:

* one page and many pages;
* empty intermediate pages and terminal empty pages;
* `next` null, missing, or no `links` at all;

## 7. Negative and fail-closed evidence

Transport-level refusals are typed, bounded and never request the refused
target. The pinned client, by contrast, goes on to consume or follow the
same input. Covered:

* self-loop, two-page and longer cycles, including other URL spellings;
* ever-advancing empty pages (the client consumed 30 pages in one `next()`;
  the guard stopped after 2–3);
* page ceiling;
* page and iterator byte ceilings at the frozen values, including the
  declared-length and gzip cases;
* deadlines before a page, during a stalled page, during a slow-drip body
  and across fast pages;
* read, connect and request timeouts;
* malformed JSON and JSON:API, with the same exception types as the client;
* malformed, relative, insecure, foreign, credentialed, fragment and
  other-path continuations (37 vectors);
* unsafe redirects (15 vectors) and redirect loops;

## 13. Remaining risks

These are expanded in qualification document section 8.

1. **Unknown link shape.** If ANTARES emits `http`, foreign, relative or
   other-path `links.next`, the canary fails closed on the first multi-page
   node.
2. **Transient outages are terminal for a P2 root.** G6.6.2B grammar has no
   renewal, so an outage spanning both attempts of one node ends the canary.
3. **Unknown floor-saturation scale on Jul07/Jul13.** Budgets bind by
   failing closed.
4. **Abandoned page threads.** After a deadline they may linger until a
   socket read ends; they can never deliver science.
5. **Continuation query content is server-defined**, as for the pinned
   client and every P1 night.
6. **Journal size.** About two events per search, embedded in the sealed
   query evidence.
7. **Redirect cookies.** A redirect hop does not replay a 3xx `Set-Cookie`.
8. **Decompression amplification** depends on the release's urllib3.
9. **No production approval.** Adopting verified canaries into the Jul07–13
   ALL-ADOPTION range requires a later Control-approved release that
   registers exactly this profile and provider SHA.
10. **No proxy-level evidence for development runs.** The no-network proof
    covers the final qualification (kernel-enforced). Development runs were
    offline by construction (fakes, socket guard). No command in the session
    addressed an ANTARES host; network use was PyPI dependency installation
    and git. A proxy-level log could not be read from this session.
