## 4. Final architecture

The parent (scientific) process keeps everything that decides science:
the P2 traversal, queries, partitions, journal events, checkpoints,
validation, authority, completion, and inside `_GuardedListing` the
pagination, continuation validation, page and iterator byte budgets, the
iterator deadline, JSON decoding (`requests.Response.json()`, the client's
own decoder) and JSON:API decoding (`_LocusListingSchema`). Natural
exhaustion is still the only completeness certificate.

The child is a transport executor only. Per request it performs one page
exchange: name resolution, connect, TLS, redirects inside the page
(validated before they are requested; their bodies are never read), status
classification without reading error bodies, and the bounded body read
(decoded bytes counted against the budget the parent sent). It returns the
exact body bytes and the charset `requests` derived, or a typed failure. The
parent rebuilds a `requests.Response` with exactly that body and encoding,
so decoding and its error types are unchanged.

The child runs only `p2_transport.py`, loaded by path as the private module
`_antares_p2_transport_child` by a `python -c` bootstrap that removes the
working directory from `sys.path`. It imports only the standard library and
`requests`. It never imports the `src` package (its READY message lists the
`src` modules loaded, and the parent requires that list to be empty), so it
cannot reach journals, checkpoints, manifests, storage, transactions,
authorizations or publication, and it writes nothing but frames to its
result pipe. Its stdio is `/dev/null`; only the two pipe descriptors are
passed. `ChildBoundaryTests` proves the module's imports (no relative import,
no `pickle`, `marshal`, `shelve`, `multiprocessing`, `copyreg`, `eval`) and
that its only `open()` reads its own source.

Error mapping (parent): the child's refusal codes map to the existing guard
classes (`P2PageBytesError`, `P2IteratorBytesError`, `P2UnsafeRedirectError`,
`P2RedirectLimitError`, `P2UnexpectedStatusError`) and to the retryable
`P2TransportHTTPError` exactly as before. Transport exceptions cross by exact
qualified name from a whitelist of `requests.exceptions` classes and are
re-raised without text, so journal `exception_type` strings and the shared
retry classifier are unchanged (`ReadTimeout`, `ConnectionError`,
`ChunkedEncodingError`, … stay retryable). Anything else the child reports
becomes `P2TransportProcessError`. Five new guard classes
(`ValueError`, so non-retryable; all in `_P2_TRANSPORT_GUARD_TYPES`, so the
journal reason is `p2_transport_guard`):

* `P2TransportProcessError` (base; unrecognised child failure);
* `P2TransportStartupError`;
* `P2TransportProtocolError` (IPC contract broken, or a request over the IPC bound);
* `P2TransportUnavailableError` (the transport already failed or closed);
* `P2TransportUnkillableError` (death not proven).

A deadline still raises `P2DeadlineError`, now with the child killed.

## 5. Process lifetime and lifecycle

* **One child per P2 night query.** `_load_p2_client` builds one
  `_GuardedListing` with one `P2ProcessTransport`. The child starts lazily
  on the first page, then serves every page of every search of that night.
  Loading the client for its identity (`client_identity`) builds a
  paginator whose transport never starts.
* **States** `NOT_STARTED → RUNNING → FAILED | CLOSED`. A typed failure that
  the healthy child reports (an HTTP status, a refusal, a transport
  exception) leaves it `RUNNING`, so the qualified per-node retry reuses it.
  A deadline, IPC violation, early end of stream, child death or startup
  failure kills it and leaves the transport `FAILED`. `FAILED` and `CLOSED`
  are final: every further page raises `P2TransportUnavailableError`.
  **No restart** for that night: a new child requires a new query, which
  for a canary means a new root.
* **End of the night.** `_run_p2_query`'s loop is wrapped in
  `try`/`finally`; the `finally` closes the listing. `close()` sends
  SHUTDOWN, waits up to `child_shutdown_seconds`, then escalates (SIGTERM,
  grace, SIGKILL, join). If the exit cannot be reaped, `close()` raises
  `P2TransportUnkillableError` and the query itself fails.
* **No orphan.** The child is in its own session (terminal signals and
  Ctrl-C reach only the parent; the child also ignores SIGINT). A
  `weakref.finalize` kills and reaps the child if the transport is garbage
  collected or the interpreter exits. A watchdog thread in the child exits
  it when its parent changes (parent killed without cleanup). A
  `KeyboardInterrupt` in the parent during a page kills the child.
* **Concurrent use** of one transport is refused (`unavailable`,
  `concurrent_use`), never interleaved.

## 6. IPC protocol `g663d.p2-transport-ipc.v1`

Frame: magic `G6D1`, big-endian `u32` header length, `u32` payload length,
the header as canonical ASCII JSON (sorted keys, no NaN/Infinity), then the
raw payload bytes. Nothing is pickled.

| Direction | Kind | Header keys (exact set) | Payload |
|---|---|---|---|
| parent → child | INIT | kind, protocol, config, hook | none |
| child → parent | READY | kind, protocol, pid, implementation_sha256, antares_modules | none |
| parent → child | REQUEST | kind, id, url, params, budget, overflow | none |
| child → parent | RESULT | kind, id, seq | 1 … `ipc_max_chunk_bytes` body bytes |
| child → parent | COMPLETE | kind, id, chunks, length, sha256, encoding | none |
| child → parent | ERROR | kind, id, code, type, status | none |
| parent → child | SHUTDOWN | kind | none |

Parent validation (any violation kills the child; `P2TransportProtocolError`):

* READY must carry this protocol, the child's real pid, the SHA-256 of the
  bytes the child executed equal to `implementation_sha256()`, and an
  empty `antares_modules` list; otherwise startup fails.
* Request ids are sequential; every reply must carry the current id
  (`type(...) is int`, so `True` is not `1`). A frame for another id is
  foreign.
* RESULT `seq` must be exactly the next chunk; empty chunks are refused;
  the running body may never exceed the request's budget.
* COMPLETE must match the received chunk count, length and SHA-256 and
  carry no payload. ERROR must be the first and only frame of its request,
  with a known code, a well-formed type name and an HTTP status in
  100–999 or null.
* Unknown kinds, extra or missing keys, bad magic, a header over
  `ipc_max_header_bytes`, a payload over `ipc_max_chunk_bytes`, invalid
  JSON or non-ASCII headers, end of stream before COMPLETE or ERROR, and
  child death are all violations.
* The parent reads with non-blocking descriptors and `selectors`; every
  byte of every frame is bounded by the request's remaining deadline. It
  never reads past the current frame.
* A REQUEST whose header would exceed `ipc_max_header_bytes`, or with an
  invalid budget or overflow code, is refused before any child is started
  or written to.

The child validates INIT and every REQUEST the same way and exits with a
protocol status on any violation.

## 7. Hard deadline sequence and bounds

At the iterator deadline (or any violation) the parent: stops the request
(reads no further), sends SIGTERM, waits `terminate_grace_seconds`, sends
SIGKILL, waits `kill_join_seconds`, and requires a reaped exit status
(`Popen.returncode` set by `waitpid`). Only then does it raise the terminal
P2 failure. If no exit status can be reaped, the failure is
`P2TransportUnkillableError` (night fails). Worst case from the deadline to
the terminal failure: 2 s + 5 s = 7 s.

The existing limits are unchanged: P2 `max_depth` 18, nodes per root 511,
nodes per night 4,095, search attempts 250,000, `crash_reserve` 4,
`max_event_bytes` 33,554,432; transport pages 64, consecutive empty pages
2, page bytes 16,777,216, iterator bytes 67,108,864, iterator deadline
600 s, connect/read timeouts 60 s, redirects 2.

New finite bounds (all in the frozen profile and its identity):

| Bound | Value | Justification |
|---|---|---|
| IPC wait | the remaining iterator deadline (≤ 600 s) | the parent's only clock for a page; no separate, longer wait exists |
| `ipc_max_header_bytes` | 65,536 | a REQUEST carries the listing URL with two short parameters (about 1 KiB) or one continuation URL; 64× margin, and far above common 8 KiB server request-line limits |
| `ipc_max_chunk_bytes` | 1,048,576 | a 16 MiB page crosses in ≤ 16 frames; bounds each read and allocation |
| `child_startup_seconds` | 30 | measured startup 0.10–0.15 s (interpreter plus `requests`); ample for a loaded, network-filesystem venv. Startup is also bounded by the iterator deadline |
| `child_shutdown_seconds` | 5 | measured cooperative shutdown 3–7 ms |
| `terminate_grace_seconds` | 2 | SIGTERM death measured at 3 ms, including a child blocked in the resolver or in trailers |
| `kill_join_seconds` | 5 | a SIGKILLed process is reaped at once unless it is in uninterruptible kernel sleep; beyond 5 s death is not provable and the night fails |

Each is a validated exact integer with a finite range in
`_P2_TRANSPORT_BOUNDS` (`test_limits_are_exact_finite_integers`).

## 8. Resolver and trailer proofs (final code)

* `PreSocketTerminationTests`: the child's `socket.getaddrinfo` blocks in a
  C-level read and writes a marker when entered. The production paginator
  with a 1 s deadline raises `P2DeadlineError`; the marker proves the child
  was inside the resolver; the loopback server received no connection. The
  child is reaped with returncode −15 (or −9 after the 2 s grace when it
  ignores SIGTERM), `os.kill(pid, 0)` raises `ProcessLookupError`, no child
  process remains, and the next page raises `P2TransportUnavailableError`
  with still one spawn.
* `TrailerTerminationTests`: a valid chunked body, the terminating chunk,
  then trailer lines forever. `P2DeadlineError` within 2 s, no record
  yielded, child reaped (−15). The server's writes fail within 1 s of the
  kill and its byte counter is identical 1 s and 2 s later.
* `LoopbackSocketTests` (G6.6.3A cases on the real child): a stalled page
  and individually fast pages across the deadline are killed and reaped; a
  slow-drip body (one byte per 100 ms, defeating the 60 s read timeout) is
  killed at the 1 s deadline and the server's drip stops by itself.
* `DeadlineDuringTransferTests`: a child that stalls in the middle of a
  frame, or streams one-byte RESULT frames without end, is killed at the
  deadline.

## 15. Residual risks (live canary only)

* **Child start on Arnor.** The canary is the first time the child runs
  under the release venv on Arnor. The new 7.1 preflight starts one
  production child offline in an empty network namespace, proves its bytes
  and stops it (returncode 0) before any live step; a failure there stops
  the procedure without burning the root.
* **Uninterruptible sleep.** A child stuck in uninterruptible kernel sleep
  (for example on a hung network filesystem) may not be reapable within
  5 s. The night then fails with `P2TransportUnkillableError` and the
  operator must report it; it can never become science.
* **Environment inheritance.** The child inherits the parent's environment
  (proxy and CA settings), exactly as the in-process `requests` did, so
  its network behaviour on Arnor is the same as before.
* The G6.6.3A residual risks that are not about threads (link shape,
  terminal transient outages, floor-saturation scale, journal size,
  redirect cookies, decompression) are unchanged and are not reopened here.
